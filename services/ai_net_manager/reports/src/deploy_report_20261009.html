1.2 小区锁定状态（直答：未锁定）

结论：没有锁定任何小区。依据（四项互证）：① API 原始字段 "executor": {"mode":"shadow","enabled":false}； ② 累计 6,620 条决策全部 action=none、状态全 NORMAL、0 建议、0 切换；③ 全程零写类 / 流式 AT（安全红线）； ④ 本固件不含 AT+QNWLOCK（§二），旧方案依赖的 ECELLMEAS / EMMCHLCK 在固件升级后已失效且旧服务已停用禁启。 开启锁小区＝需能力验证 + 现场授权 + 执行器另开（Phase 1 范围外，接口已保留）。
为什么先 Shadow：设计文档要求"可观测 > 可解释 > 可回滚 > 再自动化"。当前单小区环境下候选为空属正常， 系统的价值在持续量化"此刻网络好不好、什么时候会变坏"，为后续模型训练与切换决策积累语料。

二、设计适配（设备实测 vs 设计假设）

设计文档假设RG660MK 实测处置
AT+QENG="servingcell / neighbourcell"不支持（+CME ERROR: 4） 采集走 mipc_wan_cli + AT+C5GREG?/AT+CESQ 适配层（设计 §3.1 预留的固件适配）
邻区测量无可用只读源 候选＝历史 cell_profile 画像（设计 §8.1 降级口径，如实标注）
CA 信息（AT+QCAINFO）不支持 missing 字段显式标记，绝不填 0（设计 §3.3）
锁小区（AT+QNWLOCK）不支持 执行器保持禁用（Phase 1 默认即为禁用状态）——当前状态：未锁定（§1.2）

三、期间发现与处置

事项经过处置
历史版本冲突 设备上存在 10-08 版同类实现（services/ai-net-manager）：其信号源 ECELLMEAS 刷机后固件恒报错、 radio 全空，且每秒重试与新版争抢 AT 通道 旧版停用 + 禁自启（文件与数据完整保留于 /data/ai_net，恢复一条命令，双方 README 已注明）
关键 bug 修复 采样中 RSRP 整列丢失：子进程 stdout/stderr 拼接时（信号行无结尾换行）与驱动噪音粘成一行，被过滤器整行误删 修复（补换行 + 过滤器只匹配行首）+ 回归；修复后覆盖率 100% 并持续保持（近 500 样本复核）
安全红线对齐 10-08 曾有"流式 AT 命令→模组失联→刷机"事故复盘（首要嫌疑） 本项目全程只读探测，零写类 / 流式 AT；红线写入 README 与测试纪律
