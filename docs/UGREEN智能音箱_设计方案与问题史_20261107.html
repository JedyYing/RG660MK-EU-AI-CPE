一、系统形态与设计目标

一台 RG660MK（5G CPE）外接 UGREEN CM564 USB 声卡，盒子的麦克风与扬声器共用 plughw:2,0，构成「能听会说、本地闭环」的智能音箱。设计目标来自 2026-09-14 的《智能音箱优化设计 V1.0》，三条硬约束至今未变：

目标定义验收口径
快简单确定性问题不进大模型，本机 1~2 秒内开始回复唤醒→「在呢」≤ 2 s；报时/算术 ≤ 2 s
准天气、股价等实时信息必须来自实时数据，不能用模型常识猜答案带数据源与时间戳
稳每轮 turn_id 隔离，旧答案/迟到结果不得串入下一轮30 s 未出结果播「请稍等」，60 s 终止
为什么强调「本地」：展会与派出所场景经常没有稳定公网。设计上把唤醒、ASR、TTS、 时间/算术/灯控全部放在设备侧；只有天气、股价、知识问答才出网。断网时音箱仍然可用，只是「变笨」。

二、硬件与音频链路

环节实测配置说明与踩过的坑
麦克风CM564，plughw:2,0，48 kHz，采集增益 140/255 曾误判为「聋麦」——raw RMS 只有 70~150；后证实是信号弱而非硬件坏，靠增益与近场说话解决

VADRMS 门限 450 起 / 280 停（滞回） 可用 VOICE_VAD_ON/OFF 覆盖；换麦或换位置必须重新标定，否则「一直录」或「听不见」
回声无 AEC，靠「播报时静音采集」规避 播 TTS 期间 mute_for() 屏蔽录音，避免把自己的声音当成用户说话

分层路由（强规则优先）

优先级固定为 设备控制 > 天气/实时 > 本地时间 > 本地计算 > 大模型。 这条顺序是硬约束：「今天上海什么天气」必须命中天气而不是日期；「开灯」必须走设备控制不能进大模型。

层级典型请求处理器响应目标
L0 本地现在几点、今天几号、1+1、开灯、灯是不是开着本地函数 / smarthome.py1~2 秒内开始播报
L1 实时今天上海什么天气、移远通信股价open-meteo / 腾讯行情3~6 秒（含网络）
L2 复杂相对论是怎么回事、5G SA 和 NSA 区别在线大模型 / Hermes5~15 秒，超 30 s 播「请稍等」

四、关键设计决策（每条都对应一次实测）

决策为什么这么定实测依据
麦克风用 CM564、增益 140与扬声器同盒、走线简单；C270 麦会与 camview 抢 USB双麦对照：CM564 RMS 70~150（近场可辨），C270 600~2400（但会抢占）
ASR 用 paraformer 常驻服务whisper 单次 2.2 s，paraformer 常驻 0.78~1.6 s，且模型小当前 18 次样本：p50 0.943 s、max 1.614 s
唤醒词变体表（小提/下皮/小陈…）口音下 paraformer 稳定把「小皮」听成「小提」，单靠标准词永远唤不醒2026-09-21 实测「你好小提」；2026-11-05 实测「你好小陈」
休眠态只认完整「你好小皮」用户要求「说了休息就别轻易启动」，避免电视/聊天误唤醒休眠后单说「几点」不响应，说完整称呼才回「在呢」
热词 prompt 默认关闭把业务词表塞进 ASR 上文会污染解码，且每次 +2.2 s真实录音 A/B：开 prompt 无收益、更慢、更易出碎片
TTS 走本地 piperedge-tts 云端 403、连接重置、延迟不可控；本地合成不吃网络piper RTF≈0.76（A55），就绪 0.72~0.86 s，缓存命中 0.005 s
报时用预合成片段逐字合成「现在是 11 月 6 日上午 9 点 34 分 星期四」要 8 s改为片段拼接后 2.4 s（历史记录）
灯控走 --nowaitMatter 真灯确认要 12~19 s，语音侧 6 s 超时会误报「操作失败」发令即返回 0.3 s，实际开关由后台确认

5.2 九条验收检查项（2026-10-14 定稿）

  • 唤醒一次成功，应答「在呢」≤ 2 s
  • 报时/日期准确，与设备 date 一致
  • 算术与设备控制不进大模型（日志无 LLM 调用）
  • 天气/股价带数据源与时间
  • 连续两轮不串答案（turn_id 隔离）
  • 说「小皮休息」后静默，完整称呼可唤回
  • 环境噪音不触发误唤醒
  • 断网时本地功能仍可用（唤醒/报时/灯控）
  • 播报期间不录自己的声音（无自问自答）

六、问题史（按主题，含根因与当前状态）

6.1 麦克风：从「聋麦」到「信号弱」

现象根因处置
对着盒子说话无反应CM564 采集 RMS 只有 70~150，接近本底噪声；不是硬件坏，是灵敏度低提高采集增益到 140/255；近场说话；临时可切 C270 麦救急
切 C270 后唤醒好了但视觉异常C270 麦与 camview 抢 USB 独占回归 CM564；抓帧统一走 camview HTTP 口
换了位置后又「听不见」VAD 阈值是按旧位置标定的用 VOICE_VAD_ON/OFF 现场重标（1400/1100 用于 C270，450/280 用于 CM564）

6.2 唤醒：四次不同根因，同一个症状

时间根因修复
2026-09-21变体表缺「小提」：ASR 听对了但唤醒词不认补小提/下提/小蹄等变体（提交 d046e77）
2026-10 之后KWS 模型文件丢失，声学唤醒恒 False，全靠 ASR 兜底未恢复（当前状态），靠 ASR 文本兜底
2026-11-05asleep 只置 True 从不置 False：说过一次「休息」后整场都在休眠态唤醒成功后置 False（本轮修复）
2026-11-05变体表缺「小陈」：本次现场实际误听补小陈/小晨/小成/小城
2026-11-05whisper-cli 与 ggml 模型文件丢失，ASR 抛 FileNotFoundError切 paraformer 常驻服务（模型完好在机）
当前最大隐患：KWS 声学唤醒模型缺失。 /data/ai_cpe/sherpa-onnx/model/ 目录不存在，kws_hit() 直接返回 False。 这意味着每一次唤醒都要先做一遍完整 ASR（0.8~1.6 s）再判文本，唤醒延迟和误唤醒率都比设计值差。 恢复方式：把 keywords 模型放回该目录（或改用 paraformer 的唤醒词检测），属于待办第一项。

阶段方案结果

6.4 时间与实时信息

  • 问「现在几点」答错：① ASR 把环境音拼在问句后（「现在几点朋友后面上次很多人…」）， 而时间正则用 fullmatch 整句匹配，直接漏到大模型，模型答「我没有查时间的工具」→ 改为「句首命中且 ≤30 字即按本地时间处理」；② 设备无 RTC 电池，断电后时间漂移 → 启用 NTP （后又因 overlay 重置被关掉，属待办）。
  • 天气答英文：wttr.in 的 lang_zh 退化 → 改 open-meteo 为主源（提交 1ea1836）。
  • 股票必超时：名称解析放大到 23~29 s，7 s 快失败掐断 → 名称解析移出快路径（提交 4eb4ace）。

阶段问题结果

6.6 其它已闭环的问题

  • 灯控误报失败：Matter 真灯确认 12~19 s，语音侧 6 s 超时 → 改 --nowait，0.3 s 返回。
  • 报时慢：逐字合成 8 s → 预合成片段拼接 2.4 s。
  • 噪声误触发/自说自话：垃圾文本判定 + 连续两次垃圾即静默退场；播报期间静音采集。
  • 看门狗把进程杀错：pgrep -f voice_assistant.py 会匹配到检查脚本自己 → 改用 [v]oice_assistant.py 括号法，且按文件名精确匹配。
  • 断电丢文件：whisper 二进制/模型、KWS 模型都在一次断电后消失（/data 分区）；已改为 paraformer 常驻 + 待补 KWS。
