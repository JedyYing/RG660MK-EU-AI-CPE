# AI CPE 看板增强与真灯验收 · 设计与实现

- 日期：2026-11-02
- 设备：RG660MK-EU（OpenWrt 23.05 / aarch64，AP `jedy`，LAN 192.168.1.1）
- 看板：`http://172.25.25.224:8099/`（ZeroTier）/ `http://192.168.1.1:8099/`（LAN）
- 代码仓库：`github.com:JedyYing/RG660MK-EU-AI-CPE`（main）

## 1. 目标

1. **真灯可控**：第 5 项「智能家居控制」必须控制 Moes Matter 灯，不得用板载 LED 代理冒充通过。
2. **视觉项口径**：画面有人/无人、坐姿正常/异常都属场景状态，只要链路执行成功即通过。
3. **NPU 可视化**：看板常驻显示 MT200 NPU 的型号、算力规格、实时利用率与最近推理耗时。
4. **Token 成本可视化**：空白区展示「今日」与「近 30 天」的 token 用量及折合人民币。
5. **不再卡死**：服务重启或进程被杀后，页面不能永久停在「演示进行中…」。

```
浏览器 ──HTTP──> RG660MK aicpe_demo.py (8099)

                    │        └─ chip-tool onoff … 10 1  （Matter node 10，Moes 灯 192.168.1.224）
                    ├─ 推理：llm_gateway → 192.168.1.244:18091（笔记本 LAN 网关）→ SSH 隧道 → MT200 127.0.0.1:8090

                    └─ Token 费用：cron(15min) token_cost.py → token_stats.json（模组+笔记本 3 个 state.db 合并）
```

## 3. 关键改动

### 3.1 真灯（Matter node 10）

- 灯泡：Moes Matter 灯，MAC `20:f1:b2:5b:f4:9a`，连模组 AP `jedy`，IP `192.168.1.224`（DHCP 名 `lwip0`）。
- 配网：设备端 Hermes 已完成 on-network 配网（`chip-tool pairing code 10 <11位码>`），
  fabric 持久化在 `/data/ai_cpe/matter/kvs/`，`config.json` 的 `matter.node_id=10`。
- 驱动工厂 `drivers/factory.py` 优先级：**Matter(node_id 已配) → 涂鸦云(凭据存在) → 板载 LED 代理**。
- 新增 `drivers/tuya_driver.py`（备用路径）：云控开关，发令后轮询云端状态直至收敛，不接受“已发送”即成功。
- `smarthome.py status` 返回 `driver=matter / proxy=false`；`proxy=true` 只可能是未配网回退。

### 3.2 第 5 项验收判定

- 板载 LED（`board-led`/`proxy=true`）→ 一律 `fail`（只证明控制面通，不代表真灯）。
- 真实执行器（matter/tuya）→ 三轮 `off→on` 控制面回读，每轮要求 `False→True`；结束恢复初态。
- **现场恢复加重试**：Matter 冷会话首次调用实测 15.2s，可能超时；恢复不达标时自动重试一次（t=90），
  指标里打印 `rc/success/switch_led/初态` 便于取证。

### 3.3 视觉项（第 2 项）

- 判定：`fail` 仅当推理/判定过程本身异常（`判定异常`、YOLO 异常）；否则 `pass`。
- 「画面内无人」「坐姿异常」记为**场景状态**，不再降级为 `partial`（2026-11-02 用户明确口径）。
- 稳定性：空帧自动重抓（最多 2 次，间隔 2s），避免人刚好侧身/低头被判无人。
- 身份识别与人脸库仍作为指标展示，不参与通过判定。

### 3.4 NPU 指标

- 数据来源：`llm_gateway` 每次真实推理的端到端计时（`time.monotonic()`）。
- 指标：型号、算力规格（200 TOPS，来源项目文档）、**利用率 = 近 60s 推理占用时长 / 60s**、最近一次耗时。
- 说明：该 BSP 未暴露 NPU 硬件忙闲计数器（debugfs 无 npu/fastrpc 节点，devfreq 仅 UFS/GPU），
  因此利用率采用「推理占空比」口径，可实测、可复算，空闲时自然归零。
- 显示常驻：即使无推理记录（服务刚重启）也渲染，用 `llm.model` 兜底，显示 0.0%。

### 3.5 Token 用量与费用

- 数据源（三库合并，缺一必被追问）：
  - 模组 `/data/hermes/.hermes/state.db`
  - 笔记本 `/home/jedyying/.hermes/state.db`
  - 笔记本 legacy `/home/jedyying/.hermes/profiles/phicoteklegacy/state.db`
- 口径沿用 `hermes-usage-stats`：用量=input+output，cache 单列，峰谷价按消息时刻加权，按会话消息数分摊到天。
- 采集：`/data/ai_cpe/token_cost.py`（cron `*/15`）→ `/data/ai_cpe/token_stats.json`；看板只读缓存。
- 展示：`今日 619.7 万 tokens ≈ ¥26.40 ｜ 近 30 天 6972.1 万 tokens ≈ ¥279.80`。

### 3.6 卡死与复位

- 根因：服务重启后 `state_last.json` 仍为 `phase=running`，服务端原样加载 → 页面永久「演示进行中…」。
- 修复 1：加载 state 时若 `phase=running` 且文件 180s 未更新（运行中每完成一项就刷新），判定为中断 →
  `phase=idle`，未完成项标 `skip`，summary 写明原因。
- 修复 2：新增 `POST /reset`，人工一键复位，不必重启服务。

## 5. 已知边界

1. NPU 硬件占用率（%）无法从 BSP 读取；现口径为推理占空比（近 60s）。
2. 200 TOPS 为规格值（项目文档记载），非实测算力；与利用率分开标注，避免混淆。
3. Token 费用按 DeepSeek 官方人民币峰谷价估算，非账单实扣；缓存价按 messages 峰谷占比加权。
4. 涂鸦云通道保留但未启用（缺 Access ID/Secret），一旦写入 `.env` 即自动优先于 board-led。
5. 笔记本必须在线（本地模式经 192.168.1.244:18091 转发到 MT200）。
