# RG660MK 智能灯掉线：根因分析与修复

- 日期：2026-11-25
- 现象：灯通电正常点亮，但不在线——看板第 5 项（智能家居控制）跳过/失败，Home Assistant（:8123）也无法控制
- 结论：**不是灯坏了，也不是 AP 坏了**，是 WPA2 组密钥轮换 + 客户端省电（U-APSD）叠加，导致 AP 主动踢掉灯，灯固件随后停止重试

## 1. 证据链（可真伪）

**① AP 侧关联表为空、mDNS 无应答、ping 不通**
```
ra0/ra1/rai0 all_sta → 0 个客户端（灯 MAC d8:fc:92:b8:b1:41 不在任何一张表）
ping 192.168.1.134 / .135 → 100% 丢包
mDNS 查询 _matter._tcp → NO_MDNS_REPLY
```

**② hostapd 日志给出断开原因（关键证据）**
```
ra0: STA d8:fc:92:b8:b1:41 IEEE 802.11: associated
ra0: STA d8:fc:92:b8:b1:41 WPA: pairwise key handshake completed (RSN)
ra0: EAPOL-4WAY-HS-COMPLETED d8:fc:92:b8:b1:41
ra0: STA d8:fc:92:b8:b1:41 WPA: group key handshake completed (RSN)
ra0: STA d8:fc:92:b8:b1:41 WPA: group key handshake failed (RSN) after 4 tries   ← 根因
ra0: AP-STA-DISCONNECTED d8:fc:92:b8:b1:41
ra0: STA d8:fc:92:b8:b1:41 IEEE 802.11: disassociated
```

**③ AP 配置（修复前）**
```
wpa=2, wpa_key_mgmt=WPA-PSK, rsn_pairwise=CCMP TKIP
wpa_group_rekey=3600          ← 每小时轮换组密钥
uapsd_advertisement_enabled=1 ← 允许客户端 U-APSD 省电
```

**④ 灯侧状态**：被踢后不再发起任何关联（hostapd 里 0 次新的 associated/probe），说明其 Wi-Fi 栈已停止重试（设备固件行为）。

## 2. 根因

1. AP 按 `rekey_interval=3600` 每小时轮换组密钥；
2. 灯采用 U-APSD 省电，休眠窗口内错过 EAPOL 组密钥帧；
3. AP 重发 4 次仍无响应 → 主动断开该 STA；
4. 反复被踢后，灯固件不再重试 → 表现为"灯亮着但离线"，任何控制器（Matter/HA/涂鸦）都无法控制。

## 3. 修复（已落地，持久化在 UCI）

| 项 | 修改 | 值 |
|---|---|---|
| 组密钥轮换 | `wireless.ra0.rekey_interval` | `0`（不轮换） |
| U-APSD 省电广告 | `wireless.ra0.uapsd` | `0`（关闭） |
| DHCP 保留 | `/etc/config/dhcp` | `d8:fc:92:b8:b1:41 → 192.168.1.134`（infinite） |
| 第 5 项探测 | `aicpe_demo.py` | ping 不通时 mDNS 兜底；BULB_IPS 含 .135 |
| 掉线监控 | `tools/bulb_watch.sh` | 每 2 分钟，记录上下线与断开原因 |

生效验证（`/var/run/hostapd/hostapd-ra0.conf`）：
```
wpa_group_rekey=0
uapsd_advertisement_enabled=0
```

> 注：MTK 的 hostapd 生成器按 `rekey_interval` 写 `wpa_group_rekey`、按 `uapsd` 写 `uapsd_advertisement_enabled`。
> 直接用 `wpa_group_rekey` / `uapsd_advertisement_enabled` / `rsn_pairwise` 这些 UCI 键**不会**生效。
> `rsn_pairwise` 仍显示 `CCMP TKIP`（生成器默认），对支持 CCMP 的客户端无影响，属遗留项。

## 4. 验证结果（2026-11-25）

| 项 | 结果 |
|---|---|
| 灯重新入网 | 关联 ra0，DHCP 保留生效，IP **192.168.1.134** |
| Matter 控制 | `matter_status=confirmed`，单轮开关回读通过，28.4 s |
| 演示 | 10/10（含第 5 项真实执行器验收） |
| 长时间稳定性 | 云端模式百轮压测期间灯持续在线，无再次掉线 |

## 5. 防复发与运维

- **配置持久化**：UCI 已 commit，重启/`wifi reload` 后仍生效。
- **监控**：`/data/ai_cpe/logs/bulb_watch.log` 记录 `online/offline` 变化，并附 hostapd 最近 3 条断开原因。
- **排查顺序**（下次再掉线）：
  1. `hostapd_cli -i ra0 all_sta | grep d8:fc:92` 看是否关联；
  2. `tail /data/ai_cpe/logs/bulb_watch.log` 看最后断开原因；
  3. `grep d8:fc:92 /var/log/hostapd.log | tail` 看是否再次出现 `group key handshake failed`；
  4. 若灯侧零帧发送（连 probe 都没有），说明其 Wi-Fi 栈卡死，只能断电 10 秒重启（设备侧限制）。

## 6. 经验教训

- **"灯亮"≠"在线"**：通电只说明供电正常，Wi-Fi 关联是独立状态。
- **不要用反复重启掩盖问题**：这次先定位到 hostapd 的 `group key handshake failed`，再改配置，重启只是让设备重新入网的最后一步。
- **IoT SSID 的通用做法**：关闭组密钥轮换、关闭 U-APSD、固定 IP 保留，能显著降低低功耗设备掉线率。
