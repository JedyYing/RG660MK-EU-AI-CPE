## 三、四类差异归因(你要求的分类判定)

1. **链路丢包**: 2 包(扩展序列号 21550、21551)。经双pcap匹配(SSRC+扩展序列号)定位, 
   这两个是 PC 发送的最后 2 个包, 对应 RG pcap 尾部被在线管道超时切断的半截 record。
   => 归因: **抓包截断(工具侧)**, 非网络链路丢包。TShark 独立确认 RG 侧 0% loss。
2. **抓包程序/内核丢包**: PC 侧 tcpdump stderr = 0 dropped by kernel。RG 侧因 SSH 通道被
   主动关闭, tcpdump 未及打印统计行; 但 capinfos 与解析器一致确认前 19782 record 完整无损。
3. **分析程序丢包**: 离线解析 received == pcap PT96 record 数(19784 / 19782), 解析器未漏包。
4. **FU-A 重组异常**: incomplete_idr_nalus=0, 无缺首/末片。两端一致。

### payload 哈希差异说明(诚实标注)
双pcap比对初报 8 个 payload_mismatch。排查确认: 均为流末尾极小 RTP 包(payload 3~5字节),
RX 侧被补齐到以太网 60 字节最小帧, 尾部多 0 padding(如 5c4164 vs 5c416400)。RTP 有效载荷
开头完全一致 => **非损坏, 是 L2 最小帧 padding**。比对脚本按 UDP 原始长度而未按 IP length 裁掉
L2 padding, 属脚本口径问题, 已在报告标注。真实 payload 损坏 = 0。
