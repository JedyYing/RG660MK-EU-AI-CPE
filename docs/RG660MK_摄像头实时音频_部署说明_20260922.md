# RG660MK 摄像头「实时画面 + 声音」远程共享 部署说明

日期：2026-09-22　设备：RG660MK CPE（OpenWrt aarch64）　摄像头：Logitech C270

## 一、目标与结果

让远端同事**只用一个浏览器链接**，就能同时看到 C270 的实时画面并听到现场声音。

结果：已实现。链路实测通过，音频稳态 **32KB/s = 16kHz 单声道实时满速**。

```
┌────────── 设备 RG660MK ──────────┐
│  C270 摄像头 (libuvc/USB)        │
│        ↓                          │
│  camview:8090  纯 MJPEG 视频      │
│        ↑ 转发                     │
│  camav :8092  ① /stream  视频     │
│               ② /audio   音频 ← arecord 采 C270 自带麦克风
│               ③ /        页面(MJPEG + Web Audio 播 PCM)
└───────────────┬──────────────────┘
                │ 局域网 192.168.1.1
        ┌───────▼────────┐
        │ 笔记本 Ubuntu  │  cloudflared tunnel --url http://192.168.1.1:8092
        └───────┬────────┘
                │ 出站（不需要公网 IP / 不需要开放入站）
        ┌───────▼────────┐
        │ Cloudflare 边缘 │  https://xxx.trycloudflare.com
        └───────┬────────┘
                ▼
          远端同事浏览器（看到画面 + 听到声音）
```

## 二、为什么原来「只有画面没声音」

`camview` 是纯 **MJPEG** 服务：它只从摄像头取视频帧，二进制里**没有任何音频代码**
（`strings camview | grep -icE 'audio|pcm|snd|opus|aac'` = 0）。
MJPEG 协议本身也不携带音轨，所以浏览器端必然听不到声音。

硬件上麦克风是有的：C270 除了视频（libuvc）外，还作为 **USB Audio 设备**暴露为
声卡 `card 1 = C270 HD WEBCAM`，录音节点 `/dev/snd/pcmC1D0c`；
设备自带 `arecord`。所以只需补上「采集 + 传输 + 播放」三段。

## 三、部署步骤

### 1. 设备：部署 camav 服务

```sh
cp camav.py   /data/ai_cpe/hermes/home/
cp camav.init /etc/init.d/camav
chmod +x /etc/init.d/camav
/etc/init.d/camav enable
/etc/init.d/camav start
```

自检（四项都应正常）：

```sh
curl -s -o /dev/null -w 'page %{http_code}\n'   http://127.0.0.1:8092/
curl -s -o /dev/null -w 'snap %{http_code}\n'   http://127.0.0.1:8092/snapshot
curl -s -m 4 -o /dev/null -w 'video %{http_code}\n' http://127.0.0.1:8092/stream
curl -s -m 4 -o /tmp/a.raw -w 'audio %{http_code}\n' http://127.0.0.1:8092/audio; ls -l /tmp/a.raw
curl -s http://127.0.0.1:8092/status        # dev=plughw:1 bytes=... clients=...
```

### 2. 笔记本：起隧道

```sh
wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -O cloudflared
chmod +x cloudflared
./cloudflared tunnel --url http://192.168.1.1:8092
```

> 日志里的 `CONNECTIVITY PRE-CHECKS ... critical failures` 是对 region2 节点的告警，
> **不影响**：只要最后出现 `Registered tunnel connection ... location=sin09` 即成功。

### 3. 远端：打开链接

打开输出的 `https://xxx.trycloudflare.com` → **点一下页面上「🔊 点击开启声音」**
（浏览器策略：必须有用户手势才允许播放声音）。

## 四、踩过的坑（重要）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | `arecord` 报 `Resource busy` | C270 麦克风被 `voice_assistant` 独占（`Subdevices: 0/1`） | 解析 `/proc/<pid>/environ` 确认 `REC_DEV`；改用空闲麦克风或协调占用方 |
| 2 | 音频**开始正常、随后全部 503** | 最初「每请求起一个 arecord」，客户端断开后残留进程**独占麦克风** | 改为**常驻单例采集 + 环形缓冲广播**，并在 `finally` 中可靠回收 |
| 3 | 设备有公网 IPv6 但仍无法入站 | **移动运营商封禁蜂窝入站 IPv6**（防火墙 `tcp dport 8090` 计数恒为 0，包根本没到设备） | 放弃直连，改用**出站隧道**（cloudflared） |
| 4 | 隧道里音频吞吐只有 10~26KB/s | 中间链路按块缓冲 | 改用 `Transfer-Encoding: chunked` + 小分块 + `no-transform`；**长测稳态可达 32KB/s** |
| 5 | 隧道地址每次重启都变 | 无账号的 quick tunnel 特性 | 需要固定地址就用 named tunnel（需 Cloudflare 账号） |
| 6 | `cloudflared-linux-amd64` 在设备上报 `ELF: not found` | 架构不符（设备 aarch64） | 隧道跑在**笔记本**（x86_64），或下 `cloudflared-linux-arm64` |

## 五、已知限制

1. **音频比画面略滞后**（链路缓冲所致，前 15~30 秒尤其明显，之后趋稳）。
   页面播放器会自动追帧，不会无限累积延迟。
2. **一次只能有一个程序占用 C270 麦克风**。当前 `voice_assistant` 使用 CM564
   （`REC_DEV=plughw:2,0`），因此两者不冲突；若语音助手改回 `plughw:1,0`，
   摄像头音频会静音（需二选一，或配置 ALSA `dsnoop` 共享）。
3. 依赖笔记本上的 `cloudflared` 常驻；笔记本关机则中断。
4. 无访问口令：拿到链接的人都能看画面听声音（生产环境建议加校验）。
