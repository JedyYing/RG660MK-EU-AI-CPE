# RG660MK 5G 视频轻量DPI — Phase 0 执行摘要
生成:2026-08-28 · QRIBuddy · Phase 0 only

## 结论
两份现有 pcap 中都不存在明文 RTSP/RTP 视频流;主体流量是 WireGuard(UDP)加密隧道。
文档设定的「PC 侧对明文 RTSP/RTP 做轻量 DPI + NALU 结构检查」在当前数据上不成立。
Gate 0 = LIMITED;协议 Gate(G3)就 RTSP/RTP 目标而言 = FAIL。

## 已验证事实(capinfos + tshark,非推断)
ccmni2 (356包/28.0s/Raw IP): RTSP=0, RTP streams=空; UDP=WireGuard 21帧; 其余 TLS/HTTP。
eth1   (438包/26.6s/Ether):  RTSP=0, RTP streams=空; UDP=WireGuard 150帧; 最大流 240kB 走 103.96.8.23:8002 被识别为 WireGuard/data。

## 判定
pcap 可读=PASS;出现 RTSP=FAIL;出现 RTP=FAIL;载荷=WireGuard 加密,NALU 不可见;协议 Gate=LIMITED/FAIL。

## 为何不继续建管道
Phase 1-4(远程抓包脚本/免密SSH/systemd实时解析器/RTP算法/NALU检查)全部以"存在明文RTSP/RTP"为前提。
当前证据表明视频若存在则封装在 WireGuard 隧道内,PC侧解析器只会持续 NO_ACTIVE_STREAM,无法产出指标。

## 诚实边界
两份抓包各仅约27-28秒,无法从数据区分"没在播"与"在播但走加密隧道"。
尚未登录RG660MK,未做双抓包点实时对比,未验证20-80ms延迟——均需一个已知明文RTSP测试源,当前不具备。
