## 三、现场解决的问题（2026-11-05 ~ 11-07）

| 问题 | 根因 | 解决方法 | 验证 |
|---|---|---|---|
| 音箱喊三次没反应 | `whisper-cli` 与 `ggml-base.bin` 在断电后丢失，每次 ASR 抛 `FileNotFoundError`，转写恒空 | ASR 默认引擎切到常驻 paraformer（`:6006`，模型完好） | 日志无 FileNotFoundError；asr p50 0.94 s |
| 喊一次不响应、要喊两次 | `asleep` 只被置 True、从未置 False，说过一次「休息」后整场都在休眠态 | 唤醒成功后立即 `asleep=False` | 代码级修复 + 变体补齐 |
| 「你好小皮」第一次被忽略 | paraformer 现场把它听成「你好小陈」，变体表未覆盖 | 补小陈/小晨/小成/小城到三处变体表 | `is_sleep_wake("你好小陈")` 返回 True |
| 问「现在几点」答错 | ASR 把环境音拼在问句后，时间正则用 `fullmatch` 整句匹配 → 落到大模型，模型答「没有查时间的工具」 | 改为「句首命中且 ≤30 字即按本地时间处理」 | `classify("现在几点…噪音")` → LOCAL_DATE_TIME |
| 公网演示打不开 | 板子断电重启，cloudflared quick tunnel 换域名，旧域名 NXDOMAIN | 从 `/www/board_url.txt` 取新域名，判活后更新二维码 | 新域名 root/state/snap 均 200 |
| 摄像头画面延迟高 | 公网单帧 45 KB，经隧道 2.4~3.9 s；画面 3 s 才刷新一帧 | 外网请求缩图（13.7 KB）、内网返回原图；刷新 1.5 s；局域网恢复 MJPEG 推流 | 局域网 34 ms / 公网 1.15~2.44 s |
| WiFi 信号显示三个 dBm | chip 把所有关联 STA 拼在一起，还混入 `iw` 返回的非法值 | 只显示一个有效值；设备名移到「接入终端」清单 | HONOR-90 -74 dBm + 清单 |
| 「有线 2」但只有一根网线 | ARP 里 `192.168.1.106`（STALE、无租约）被算成在线；MLO 多链路 MAC 重复计数 | 排除 STALE；按 WiFi 设备租约 IP 去重 | 4 → 3（WiFi 2 · 有线 1） |

## 四、当前遗留（现场已知）

1. **KWS 声学唤醒模型缺失**：`/data/ai_cpe/sherpa-onnx/model/` 不存在，`kws_hit()` 恒 False，
   唤醒全靠 ASR 文本兜底（每次先跑 0.8~1.6 s 转写）。恢复模型后唤醒延迟可降到 200 ms 级。
2. **NTP 未启用**：`system.ntp.enabled=0`，设备无 RTC 电池，断电后时间会漂（影响报时）。
3. **公网域名不固定**：quick tunnel 与进程绑定，断电/重启必换域名，物料（二维码）需同步更新。

## 六、现场纪律（避免重复踩坑）

- 演示期间**不要给板子断电/重启**：cloudflared 会换域名，二维码当场作废。
- 改 `aicpe_demo.py` 前先 `scp` 设备版回本地 diff：设备端可能比本地副本新。
- 语音问题先读 `/data/ai_cpe/logs/voice.log` 的 `[miss]` / `[LATENCY]` / `[TURN]` 行，
  不要凭感觉调 VAD 阈值或换模型。
