# 设计说明：8099 看板摄像头画面叠加人脸识别框

- 日期：2026-11-05
- 设备：RG660MK（OpenWrt 23.05 / aarch64，MediaTek T930）
- 目标页面：`http://192.168.1.1:8099/`（AI CPE 八大功能演示看板）
- 代码：`services/aicpe_demo/aicpe_demo.py`（提交 `147f510`）
- 关联能力：本地 NCNN 视觉服务 `127.0.0.1:8765`（RetinaFace + MobileFaceNet + 本地人脸库）

## 1. 需求

用户要求：摄像头画面里识别到人脸时，直接在画面上显示出人脸识别框（此前只有下方「AI 视觉检测」
卡片的文字结论，画面本身是干净的原始帧）。

同时澄清一个数据口径：页面 CPE 信息栏里的「温度」是 **RG660MK 板载 SoC 温度**，
不是模组温度、不是笔记本/MT200 的温度。

## 2. 数据流

```
C270 (UVC) ──► camview :8090 /snapshot
                     │
        ┌────────────┴─────────────┐
        │                          │
   GET /snap                  GET /faces
   (页面 <img>)               (前端覆盖层数据)
        │                          │
   写 /tmp/aicpe_board_last.jpg    │ 读同一帧文件（保证框与画面同帧）
        │                          ▼
        │                  POST 127.0.0.1:8765/vision/face
        │                  （RetinaFace 检测 + MobileFaceNet 比对）
        │                          │
        ▼                          ▼
   浏览器显示原始帧        JSON: w/h + faces[{bbox, subject_id,
                                  matched, similarity, score}]
                                   │
                                   ▼
                    前端 #fov 覆盖层按百分比画框 + 标签
```

关键点：`/faces` **不自己抓帧**，而是复用 `/snap` 刚落盘的那一帧。这样框和页面显示的画面
是同一帧，人脸移动时不会出现"框追不上脸"的错位。

## 3. 接口

### GET /faces

```json
{
  "ok": true,
  "w": 640, "h": 480,
  "faces": [
    {"bbox": [328.4, 66.9, 524.7, 342.9],
     "subject_id": "self", "matched": true,
     "similarity": 0.855, "score": 0.997}
  ],
  "ts": 1793823892.037
}
```

- `bbox` 为像素坐标 `[x1,y1,x2,y2]`，前端按 `x/w*100%` 转百分比定位。
- 无人时 `faces: []`；取帧失败或视觉服务不可用时 `ok: false` + `error`。
- 按 `(mtime_ns, size)` 缓存：同一帧只推理一次；缓存命中实测 0.01 s，未命中 0.70–0.96 s。
- `_FACE_INFER` 锁让并发请求排队复用同一结果——ai_service 的推理信号量是
  `acquire(blocking=False)`，不排队会直接 429（多客户端同时刷页面时必然发生）。
- **失败结果不写缓存**，否则同一帧会一直返回上一次的 Connection refused。

## 4. 前端渲染

- `#camstage`（`position:relative`）包住 `<img id="cam">`，`#fov` 绝对定位铺满
  （`pointer-events:none`，不挡点击）。
- 每个 face 生成 `.fbx` 绝对定位 div，`left/top/width/height` 全部用百分比 →
  页面缩放、手机竖屏、投屏分辨率变化时框都不会偏。
- 标签 `.flb`：默认贴在框上方；`y < 10%` 时加 `.in` 类移到框内，避免贴顶被
  `overflow:hidden` 裁掉。
- 配色：已匹配身份 = 绿色框 + 姓名 + 相似度（如「本人 85%」）；
  检测到但未入库 = 黄色框 +「未录入人脸」。无人不画框，不误报。
- 画面刷新从 1.5 s/帧 改为 **3 s/帧**，与单帧 0.7 s 的推理成本匹配；
  `/state` 轮询仍为 1.5 s（状态文字不受影响）。

## 5. 视觉服务可用性（自愈）

`ai_service`（8765）在板子上**没有 init 自启**，重启后会静默缺失，
表现就是框永远不出现、身份识别永远"未匹配"。

处理：`/faces` 失败时调用 `ensure_ai_service()`，限频 120 s 执行
`/data/ai_cpe/demo/services/start_ai.sh`。实测 kill 掉服务后第一次请求返回
`Connection refused`，2–4 s 后自动恢复 `ok=true`。

## 6. 温度口径

看板 `cpe.temp_c` 取自 `/sys/class/thermal/thermal_zone0/temp`，该 zone 的
`type = soc_max`（SoC 最高结温）。

实测对照（2026-11-05 12:20 CST）：

| zone | type | 温度 |
|---|---|---|
| 0 | soc_max | 65.6 °C |
| 5 | cpu0 | 65.6 °C |
| 9 | ap_ntc | 54.0 °C |
| 10 | ltepa_ntc（模组 PA） | 46.8 °C |
| 13 | pmic_temp | 52.0 °C |

页面 chip 文案已从「温度」改为「SoC温度」并加 `title` 说明来源，
避免演示时被理解成模组温度。

## 7. 实现中踩到的坑

1. **PIL 在 aicpe-board 进程里不可用**：`import PIL` 报
   `libtiff-cfa08caa.so.6.2.0: No such file or directory`（venv 的 pillow.libs
   没进 LD_LIBRARY_PATH）。改为自行解析 JPEG SOF 段取宽高（`jpeg_size()`），零依赖。
2. **ai_service 429**：并发请求撞信号量，见第 3 节。第一版没有排队，多个客户端时框会闪。
3. **提示图错位**：`/snap` 在判定摄像头被遮挡/全黑时返回提示图，此时必须删除
   `/tmp/aicpe_board_last.jpg`，否则框会画在提示图上。
4. **失败缓存**：第一版把失败结果也写进缓存，导致服务恢复后同一帧仍返回旧错误。
5. **前端定时器**：原来 `/snap` 刷新写在 `/state` 的 tick 里（1.5 s）；拆出独立
   3 s 定时器后，`cameraFail()` 的 2 s 重试逻辑保持不变。

前端改动仅在摄像头面板外层加了容器和覆盖层，回滚风险低。

## 9. 验证方法

```sh
# 后端：当前帧是否返回 bbox
curl -s http://192.168.1.1:8099/faces

# 缓存命中（两次 ts 相同）
curl -s http://192.168.1.1:8099/faces; curl -s http://192.168.1.1:8099/faces

# 自愈：杀掉 8765 后第一次失败、4s 内恢复
ssh root@192.168.1.1 'kill $(cat /data/ai_cpe/demo/run/ai-service.pid); curl -s 127.0.0.1:8099/faces; sleep 4; curl -s 127.0.0.1:8099/faces'

# 渲染：把 enroll.jpg 当画面、注入真实 bbox 的静态页，headless chrome 截图核对框位
```

已知边界：侧脸/低头时 RetinaFace 仍能框出人脸，但 MobileFaceNet 相似度常低于
`similarity_threshold=0.52`，会显示黄色「未录入人脸」——这是预期行为，不是故障。
正脸实测相似度 0.855（多次录入后）。
