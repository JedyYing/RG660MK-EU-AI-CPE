## 根因（互不相同，逐一查明）
- **R1 主机-设备网线链路断**：09:09:45 主机 USB 网卡（enx9c69d3c6b35d）丢失载波（NO-CARRIER），
  10:24-12:24 全程守望 carrier=0。设备本身存活（其 Wi-Fi SSID 持续在空中广播）。
- **R2 公司 VPN 劫持 v4 路由**：corplink（utun）把 192.168.1.1/32 及 ::/1 路由劫入隧道，
  VPN 开启期间裸 192.168.1.1 不可达（IPv6 fdc3 因 /64 更具体不受影响）。
- **R3 三流接收端未部署**：刷机后 rtg3_probe(8094)/camav6(8092) 尚需重新部署；
  make_qr 仅在"设备可达 + 接收端在跑 + 公网 v6 存在"三条件满足时才出有效二维码。
- **R4 麦克风未接入**：设备 USB 总线全程无设备（守望两轮零命中）→ 语音链无法建立。

## 处置与固化
- **QoS 仿真 1 行 bug 修复**：qos_sim.py 收尾写 JSON 时 `res["external"]` 初始为 None 导致
  TypeError 崩溃（示例数据其实极佳：控制 RTT 32.2ms→2.62ms）。已改 `external: {}`；
  UDP socket 加 SO_REUSEADDR；run_qos_demo.sh 增加残留进程清理（防 Address in use）。
- **桌面连接自愈**：scripts/rg660mk_demo_helper.sh —— fdc3 IPv6 优先、v4 兜底，
  两个桌面快捷方式已切换至该助手（.bak_v4_20261009 为旧版备份）。
- **一键恢复流水线**：scripts/rg660mk_recover.sh —— 链路恢复后自动：
  清残留 → 推送修复脚本/接收端 → 防火墙放行 8092/8094/8095 → 起接收端 →
  自检 → make_qr 复验（二维码重生）→ 看板复起 → QoS 重跑取回。
- **链路守望**：载波 15s 级轮询 + fdc3/LL 双路探测，恢复即落 /tmp/link_back.marker 并通知。
