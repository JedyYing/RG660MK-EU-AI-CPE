## 一、结论摘要

本轮工作把语音助手从「能跑通」推到**关键路径可靠**：修复了三个会导致用户听到错误答复的缺陷，把实时行情从「我查不了」变成 0.3 秒正确播报，并按设计文档落地了新疆口音专项的 P0/P1 逻辑层。

**已完成且有设备实测证据的**：分层路由与轮次隔离、实时行情处理器、「拒绝不得成为终答」机制、Hermes 输出清洗、端到端延迟优化、口音纠错逻辑层、唤醒可用性修复。

**尚未完成的**是口音识别率的**量化验收**——这部分必须在真机上用真实新疆口音录音完成，离线测试无法替代。详见第四节。

## 二、改进了什么

### 2.1 分层路由与轮次隔离（09-14，提交 `491ee3d`）

**问题**：多轮对话中上一轮的答复会串到下一轮；慢查询没有任何反馈，用户不知道设备是否还在工作。

**做法**：

- `dispatch()` 按设计文档 §2.1 分层：设备控制 → 天气 → 行情 → 日期时间 → 本地计算器 → LLM 函数调用兜底 → Hermes；
- 每一轮分配独立 `turn_id`，过期轮次的回复直接丢弃，不再污染新一轮；
- 30/60 秒双超时：30 秒播一次「请稍等。」（不打断后台），60 秒才放弃。

### 2.2 实时行情：从「我查不了」到 0.3 秒正确播报（09-18）

**问题现象**：问「请查看移远通信的收盘价」，答「我查不了股市行情」。

**根因是三个缺陷叠加，缺一不可**：

1. **主因**：`dispatch()` 把模型的回绝文本当成最终答案直接播报（1.5 秒返回），**Hermes 从未被调用**——而实测 Hermes 本身能答对，耗时约 29 秒。
2. 设计文档 §2.1 的 L1「实时联网」层只实现了天气，行情没有处理器，只能落到 L2。
3. **即使修好路由也仍然是坏的**：`hermes_ask()` 返回的 stdout 开头是英文推理框（`┌─ Reasoning ─┐`），而 `speak()` 先截断 120 字符再做中文占比过滤，实测中文占比 0.03 被判定为乱码，用户会听到「回复内容暂时无法播报」。

**做法**：

- 新增 L1 行情处理器：腾讯 `qt.gtimg.cn` 为主、新浪 `hq.sinajs.cn` 为备、`smartbox.gtimg.cn` 做名称检索；
- `resolve_symbol()` 三级解析：显式代码 → 本地别名表（含已观察到的 ASR 形近误听「亿元通信／一元通信」）→ 联网检索；
- 按行情时间戳区分「收盘」与「最新价」，名称一律用接口返回的正式名，避免把误听的名字念出来；
- 「拒绝不得成为终答」两道闸：`is_capability_refusal()` 识别回绝措辞，`needs_live_data()` 拦截「实时数据类问题却不带工具作答」（编造数字比回绝更糟）——两者都转 Hermes；
- 新增 `extract_hermes_answer()`，从 stdout 末尾取连续中文段落，剥掉推理框与 `session_id`；
- `LLM_OR_HERMES` 移出 7 秒快速失败集合（它现在会升级到 Hermes，实测约 29 秒），改走 30/60 双超时。

**效果（设备实测，2026-09-18 收盘后）**：

| 提问 | 结果 | 耗时 |
|---|---|---|
| 请查看移远通信的收盘价 | 移远通信今天收盘72.54元，跌1.12元，跌幅百分之1.52。 | 0.33s |
| 移远通信今天股价多少 | 同上 | 0.28s |
| 上证指数今天收盘多少 | 上证指数今天收盘3911.87元，涨36.27元，涨幅百分之0.94。 | 0.32s |
| 亿元通信股价（实测误听） | 正确解析到移远通信 72.54 | 0.32s |
| 今天美元兑人民币汇率多少 | 回绝被拦截，转 Hermes | 1.74s 后升级 |
| 今天有什么新闻 / 92号汽油多少钱一升 | 同上，均不再播报回绝 | — |

Hermes 输出清洗实测：`raw=1970 字符 → answer=74 字符`，中文占比 0.59，无推理框与 `session_id` 残留，可正常播报。

### 2.3 端到端延迟优化（09-18，随 `af9af36` 固化）

| 项目 | 改进前 | 改进后 |
|---|---|---|
| 固定提示音（「在呢，请说」等） | 每次联网合成 | 本地缓存 + 部署时预热，预热后零网络 |
| whisper 音频上下文 `-ac` | 固定 1500 | 按音频时长动态计算（保留一秒余量） |
| ASR 单次转写 | 无有效上限（90s） | 8 秒硬上限，失败返回空 |
| 唤醒收尾等待 `end_sil_ms` | 2000ms | 800ms |
| 天气查询超时 | 8s / 10s | 2s / 4s |
| 灯控超时 | 30s | 6s |
| 超时预算 | 一刀切 | 只有确定不升级的意图才享受 7 秒快速失败 |

另新增 `[LATENCY]` 日志（`asr_s` / `tts_ready_s`），后续可量化复核。

### 2.4 新疆口音识别 P0/P1 逻辑层（09-20，提交 `cabb03b`）

依据《RG660MK 智能音箱新疆口音识别优化设计 V1.0》，落地口音专项的离线逻辑层：

- **新增 `accent_correct.py`（275 行，纯 stdlib）**：内置业务词表拼音映射（设备端不依赖 pypinyin）；口音模糊音节等价类覆盖翘舌／平舌合并、前后鼻音合并、n/l 合并、f/h 相混、r 弱化；`correct_command()` 做音节级编辑距离 ≤1 的**受限纠错**，只把疑似口音误识别的控制类短句拉回已知命令，且返回原文／纠正／规则／距离，可解释可回滚；
- **集成位置**：口音纠错挂在 `classify()` 的**最末兜底位**——任何标准普通话意图先命中就直接返回，绝不进入纠错，保护基线不退化；
- **新疆地名**：CITIES 与天气链路补入乌鲁木齐、喀什、伊犁、克拉玛依、吐鲁番等 14 个地名。

设备端实测抓取：

```
[ACCENT] '打开客厅登' -> '打开客厅灯' (dist=0)  → DEVICE_CONTROL / control_bulb / on
[ACCENT] '关闭客厅登' -> '关闭客厅灯' (dist=0)  → control_bulb / off
[ACCENT] '打开卧市登' -> '打开卧室灯' (dist=0)  → control_bulb / on
打开窗连 -> 打开窗帘（文本纠对；当前无窗帘工具，按预期走 LLM 兜底）
乌鲁木齐/喀什/伊犁/克拉玛依/吐鲁番/库尔勒/哈密 → WEATHER + 城市提取正确
```

### 2.5 唤醒可用性修复（09-20 晚，提交 `32e75b6` + `d5e9de4`）

**问题**：用户实测「你好小皮」多次失败或答非所问。

**定位**：抓取真实录音做同一音频 A/B 对比，量化出 whisper `--prompt` 热词偏置是**固定成本 +2.2~2.5 秒**（约为基线 2 倍，与音频长度无关），且在真实音频上**判定为负面**：

| 模式 | 「你好小皮」转写结果 | 影响 |
|---|---|---|
| 无 prompt | `你好下題` | 接近唤醒词，可正常唤醒 |
| 全量热词 prompt | `阿梅，鲁，河田` | 被热词表（乌鲁木齐／和田等）劫持 → 误落天气 → 答「你想查哪个城市」 |

**修正**：热词 prompt 改为**默认关闭**（机制保留，`VOICE_ASR_PROMPT=1` 一键启用）；唤醒／待机路径停用 prompt，命令路径保留机制待真机 A/B；`strip_wake()` 全量收敛循环唤醒词，纯唤醒呼叫回「在呢／我在听」，不再把 `你好下皮×75` 这类循环输出当命令送后端；唤醒词变体补入实测到的「下题」。

## 四、还差什么

### 4.1 真机验收缺口（阻塞量化目标，必须用真实录音完成）

这是本阶段**最主要的未完成项**——离线逻辑层已证明可靠，但识别率的量化改善没有证明：

1. **CER／命令准确率的真机验收**：需按设计 §7 采集新疆口音开发集／验收集（各 300–500 句）真实录音，跑基线 vs 优化后对比。当前编辑距离阈值与混淆规则均为**待真机混淆矩阵校准的初值**（设计 §6.3 明确要求「从真实测试集统计，不凭印象定死」）。
2. **whisper `--prompt` 的真实增益**：命令路径的热词偏置目前默认关闭，需真实口音录音 A/B 通过后才能启用。
3. **VAD 首尾完整率**：设计目标 ≥98%，需真人近讲／远讲录音统计。
4. **端到端 P95 时延**：设计 §9 要求 `--prompt` 不显著增加时延，待真机测。

### 4.2 待查与未复测

5. **真人语音端到端未复测**：09-18 行情修复的验证全部是「文本 → 真实服务调用」，唤醒 → ASR → 播报的完整链路本轮未复测。
6. **个别转写为空的成因未查清**：上机时出现过两次唤醒转写为空 `''`，现场抓录分析中。
7. **解码循环率未统计**：whisper base 在少量音频上会陷入重复循环（合成音频「打开卧室灯」无 prompt 时输出 `打开握时登`×36，耗时 6.8s；另有样本循环且截断在半个 UTF-8 字符上触发 `UnicodeDecodeError`）。当前 `transcribe()` 捕获后返回空、降级为「请再说一下，我没听清」，**安全但体验差**；真实录音下的循环率需统计。

### 4.3 已知问题（非本轮引入）

8. **whisper 延迟数据不一致**：README 记录「base ~9.6s/5s 片段」，而 09-20 上机实测为 2.43~2.58s，两者存在量级差异，需核实并统一文档口径。
9. **人脸检测无专用模型**：`face_detect=null`，用 pose 关键点（鼻子+眼睛）近似判断人脸可见性。
10. **坐姿检测个别发音被完全漏听**：转成「嗯」或空，属语音识别固有问题。
11. **YOLO 人计数偶有误检**（2 人 vs 1 人），已从播报中移除计数规避。

### 4.4 条件触发项

12. **P2 模型适配**：仅当真机验收集出现大量「音频完整但声学识别系统性近音错误」时，才进入设计 §7.2 的 Adapter/LoRA 或供应商自定义声学模型。P0/P1 逻辑层已备好，可先上真机收数据。
13. **实时问答的答案质量**：本轮只解决「不再播报回绝」。汇率类问题的答案质量取决于 Hermes 自身选源——实测其返回 Frankfurter 的「昨日」参考价并自述为参考价，该选源问题未改进。

### 4.5 工程收尾

14. 8 个提交已推送至 `origin/fix/voice-assistant-router-turn-timeout`，但**尚未合并到 `main`**。
15. 工作区有较多未跟踪文件（`reports/`、`docs/` 下的报告与 PDF 等），未纳入版本管理。
