## 三、whisper --prompt 时延实测（设计 §9 待验证项，本次量化）

设备 whisper.cpp 1.9.3-dev / ggml-base / Cortex-A55，交叉顺序重复测量：

| 条件 | 3.55s 短音频 | 5.61s 音频 |
|---|---|---|
| 无 prompt | 2.43 / 2.44s | 2.57 / 2.58s |
| 全量热词 prompt（144 字） | 4.67 / 4.72s | 5.05 / 5.06 / 5.08s |

**结论：热词 prompt 是固定成本，每次转写 +2.2~2.5s（约为基线 2 倍），与音频长度无关。**

由此完成两处调整（已在 32e75b6 提交并上机）：

1. **唤醒/待机路径停用 prompt**（`transcribe(use_prompt=False)`）——
   唤醒词不在热词表内，待机对每条环境语音都要转写一次，加偏置只有延迟与
   CPU 空耗。实测：小皮 2.23~2.25s（无）vs 4.40~4.45s（有），两者均正确唤醒；
   停用后唤醒恢复原基线速度。
2. **命令路径保留 prompt**（设计 §6.1：面向设备名/房间/命令/地名词）。

> 待真实测试决定：命令路径 +2.2s 换专有词命中率是否值得（词表长度是可调旋钮：
> 曾测得 51 字版约 +1.5s；建议用真实新疆口音录音对比准确率后再定）。

## 四、发现与边界（需真机测试关注）

1. **解码循环**：少量音频上 whisper base 会陷入重复循环（合成 TTS "打开卧室灯"
   无 prompt 时输出 `打开握时登`×36，6.8s；"打开客厅灯" 样本循环且输出截断在
   半个 UTF-8 字符上 → `UnicodeDecodeError`）。transcribe() 捕获后返回空，
   等效超时 → 走"请再说一下，我没听清"，安全降级。
2. **prompt 与循环的互动**：带 prompt 时个别循环样本会越过 `ASR_TIMEOUT=8s` →
   空结果（超时防护正常工作）；但也有反向样本（同一音频无 prompt 循环、
   带 prompt 反而正确 4.6s 解出）。真实录音下的循环率需统计。
3. 以上均为合成音频观察，**真实新疆口音录音的 CER/命令准确率/循环率待按设计 §7
   验收集验收**；混淆规则阈值仍为待校准初值。
