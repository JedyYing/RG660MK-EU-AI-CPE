## 1. 成果与证据边界

今天完成语音采集、ASR 文本处理、意图路由、天气接口、问答模型和灯控播报的连续排查与修复。代码已在 RG660MK 部署，用户反馈“基本修复了”。本报告区分代码测试、真实服务调用和真人语音日志，不将离线测试通过等同于整机验收完成。

## 2. 硬件与软件拓扑

Ubuntu 22.04 笔记本 → 网线 → RG660MK（192.168.1.1）→ USB Hub → UGREEN CM564 麦克风 → 耳机输出。

语音助手运行在 RG660MK，不运行在笔记本。笔记本用于 SSH、编辑、测试、报告和 Git 管理。RG660MK 上 CM564 为 ALSA card2，录音与播放均指定 plughw:2,0。

处理链路：CM564 / arecord 48kHz → VAD 端点检测 → WAV 数字增益 ×4 → whisper.cpp 本地中文转写 → 意图分类 → 本地工具 / LLM / Hermes → edge-tts / mpg123 / aplay → CM564 耳机口。

主要部署文件：/data/ai_cpe/voice_assistant.py、/data/ai_cpe/vad.py、/etc/init.d/voice_assistant。仅通过 init 服务重启，避免手动启动多实例争用音频。

## 4. 第一轮：音频与路由修复

发现一：VAD 用原始 PCM 能量与 RMS 450/280 门限比较，而 ×4 增益发生在 VAD 成功之后，弱声可能提前被丢弃。修复为 VAD 判断时将能量乘 4，输出保持原始 PCM，再由主程序对 WAV 放大一次，避免双重增益。

发现二：ASR 只取最后一行转写，且不检查退出码。修复为合并全部有效行；非零退出码拒绝输出；过滤括号音效标注。录音前清除旧 WAV，固定录音使用 check=True，防止录音失败后复用上轮音频。

发现三：时间意图仍可由“今天／现在／时间”等宽泛词命中。改为完整明确问句匹配，保留设备控制、天气的优先级。计算器去掉句尾问号。

发现四：单字“皮／吉”等可误唤醒，且唤醒与命令同句时命令被丢弃。改为句首称呼匹配，兼容逗号和已观察到的尾音误识别；保留“你好”兼容入口；将同句剩余文本交给路由。

VAD 有效语音下限改为 180ms，不把前置静音算作语音；保留 150ms 尾音；退出时回收录音进程。空转写给出重说提示。连续对话在 24 秒未检测到语音后回到待机。

10:00:34 完成首轮部署；启动 rec=plughw:2,0、play=plughw:2,0、vad=True，单助手进程，ALSA capture 为 RUNNING。

## 5. 第二轮：相同提示背后的不同服务故障

10:02:38 / 10:02:56：ASR 正确识别“今天上海什么天气”；天气请求返回 CERTIFICATE_VERIFY_FAILED / certificate has expired。故障是天气服务证书，不是听不清。

10:03:26：算式被识别为“一加一等一節”；本地计算器未命中，进入问答。10:03:40 返回 HTTP 400 / Invalid model name，模型为 deepseek-v4-pro。

共同掩盖因素：TTS 按中文占比过滤英文异常文本，导致两类服务故障都变成“抱歉，我没听清，请再说一次”。

修复天气：原 wttr.in 失败后查询独立的 Open-Meteo HTTPS 接口，始终保留证书校验；天气码映射为中文；接口失败明确说“天气服务暂时连接失败”。

修复算式：仅对观察到的“等一節／等一节”尾音做归一化，再要求整串通过算式白名单；修正等号后有数字时被错误拼接成另一算式的问题。继续使用 AST 白名单，不使用 eval。

修复模型：/v1/models 虽列出 deepseek-v4-pro，实际调用返回 400；deepseek-v4-flash 实际回答 2。默认语音模型切到 flash，支持 VOICE_LLM_MODEL 覆盖；Hermes 显式传同一模型。LLM 已直接返回答案时不再丢弃并重复调用 Hermes，限制回答长度与格式适合语音。

10:16:04 完成第二轮部署。模块真实调用上海天气返回阴、26.8℃、体感 27.1℃、湿度 46%；实际误识别算式返回 2；相对论返回中文答案。这些数值是当时接口结果，不是固定播报内容。
