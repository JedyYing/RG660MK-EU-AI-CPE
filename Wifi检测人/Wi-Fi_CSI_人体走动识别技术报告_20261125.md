# Wi-Fi CSI 人体走动识别技术报告

## ——RG660MK-EU 实测：原理、算法、五轮实验、固件瓶颈与 MTK 支持诉求

- **版本**：v2.0（完整版）
- **日期**：2026-11-25
- **生成者**：hermes
- **平台**：RG660MK-EU（MediaTek T930 + MT7992，OpenWrt 23.05，Wi-Fi 驱动 CSI fw 022）
- **结论**：CSI 原始 I/Q 可稳定采集并解析，但当前固件的 proc 模式只提供“一次性快照”，且四链混采、无连续上报；五轮人体走动实测均未检出（走/坐运动分比值 0.97–1.06）。**基于 CSI 的走动识别在当前固件上不可行，卡点是数据源而非算法。**

## 一、摘要

本报告回答三个问题：

1. Wi-Fi CSI 能不能用来识别人走动？——原理上可以，CSI 的幅度/相位会随人体穿过链路而变化。
2. RG660MK 能不能采到 CSI？——能。按 MTK《Connac3 CSI Spec Requirement v1.2》用 mwctl set csi 可读出每子载波 I/Q（2.4G 64 点、5G 80MHz 256 点）。
3. RG660MK 现在能不能做出走动识别？——不能。固件 022 的 CSI latch 是一次性的（csi=1 后只锁存 1–2 个 PPDU），必须每 100ms 重臂（re-arm，即 csi=0/csi=1 重新启动 CSI 锁存）；重臂会重复回放旧帧，且单链锁定命令无效（四链幅度差 5 倍）。五轮实测本底噪声 0.32–0.48，走动信号被完全淹没。

## 二、背景与目标

### 2.1 为什么关注 CSI

华为与澳门电讯的 AI-FTTR 服务把 Wi-Fi 感知作为卖点：不用摄像头、不用穿戴设备，通过 Wi-Fi 信号感知家中人员活动，并结合干扰模型自动调整发射参数。

这类方案的核心不是 RSSI（单个强度值），而是 CSI（Channel State Information，信道状态信息）：每个子载波上的复数信道响应，包含幅度和相位，能反映多径、遮挡、微小位移。

### 2.2 能力分层

① 邻居干扰检测 / 自动选信道：标准 Wi-Fi 统计即可，PoC 可做
② 已连接设备的 RSSI/SNR 波动：粗粒度活动感知，可做
③ 无设备人体走动感知：依赖 CSI，本报告的主题
④ 华为式 10 万场景模型 + FTTR 闭环：商用方案，不可直接复制


本报告只讨论 ③：人不需要携带设备，靠 Wi-Fi 链路本身感知走动。

## 三、CSI 原理

### 3.1 信道与子载波

OFDM 把信道分成几十到上千个子载波。接收机对每个子载波估计一个复数系数：

h(f) = I(f) + j·Q(f)


- I：同相分量（In-phase）；
- Q：正交分量（Quadrature）；
- 两者由接收机用 0° / 90° 两路本振下变频得到，是复数基带的直角坐标。

换成极坐标：

幅度 |h| = sqrt(I² + Q²)    → 该子载波被衰减/增强多少
相位 φ   = atan2(Q, I)      → 传播相位（距离、时延、反射路径）


### 3.2 为什么人走动会改变 CSI

人体主要成分是水，穿过发射端与接收端之间的链路时会：

1. 遮挡直射路径（幅度下降）；
2. 改变反射/散射多径（幅度和相位同时变化）；
3. 产生多普勒（相位随时间变化）。

2.4GHz 波长约 12.5cm，5GHz 约 5.7cm。人对 5G 的相位影响更大，但 5G 绕射/穿墙更差；2.4G 覆盖好、干扰多。

### 3.3 菲涅尔区与走位

走动要“有效”，人必须穿过链路的**第一菲涅尔区**。2 米链路、2.4GHz 时中点半径约 25cm，5GHz 约 16cm。正确走法是**垂直穿过** CPE 与终端之间的连线；沿连线走等于身体一直挡着，只产生一次扰动；在连线外侧平行走，只能切到边缘能量。

### 3.4 幅度与相位怎么选

- **幅度**：稳健，受 CFO/SFO（载波/采样频偏）影响小，适合做“有人/没人、走/静”的粗粒度判断；
- **相位**：对厘米级位移更敏感，但逐帧漂移，需要参考帧/校准，适合呼吸、手势等精细感知。

本报告的实现只用幅度，相位留作后续。

### 3.5 测量拓扑（谁测谁）

手机 HONOR 90（发射端） ──上行 QoS Data 帧──▶ RG660MK CPE（接收端，MT7992）
                                                    │
                                            CSI 在 CPE 侧测量


- **CSI 是 CPE 测的**：RG660MK 的 MT7992 在 ra0（2.4G）/ rai0（5G）接收手机发来的上行帧时，逐子载波估计信道；
- 不是手机测 CPE，也不是第三方抓包/监听；
- 手机 2.4G MAC：92:77:ac:52:6a:d0；5G MAC：82:44:e5:60:86:29——手机对每个 SSID 使用随机 MAC，但 DHCP 主机名都是 HONOR-90，是同一台手机；
- 笔记本 4c:44:5b:6c:4f:bc 是第二个 STA，仅作对照；
- 人走动时改变的是“手机 → CPE”的上行信道，所以 CPE 测到的幅度/相位随之变化。
- **反证一**：CSI 帧的 Tag 7（发送方 MAC）是手机 MAC（92:77:ac:52:6a:d0 / 82:44:e5:60:86:29）；CPE 自己的 BSSID 是 00:0c:43:26:60:10，从未出现在 CSI 帧里。
- **反证二**：Beacon 测试里 CPE 只收到邻居 AP（f8:9a:78:08:cd:24/29）的 beacon，收不到自己的 beacon——说明 CSI 只能测“收到的帧”，不能测自己发的信号。
- 如果反过来去测 CPE 发的下行信号，需要手机侧支持 CSI 输出（手机驱动不开放）；因此 AP 侧测量是标准做法。

## 五、数据采集方法

### 5.1 触发帧的选择

| 触发帧 | 需要终端 | 实测速率 | 能否做走动检测 |
|---|---|---|---|
| Beacon (32) | 否 | 0.17–0.5 帧/s | 不能，4s 窗只有 1–2 帧 |
| QoS Data (34) | 是（已关联 STA） | 0.1–0.8 帧/s（只 csi=1 一次） | 不能 |
| QoS Data + 10Hz 重臂 | 是 | 76–108 帧/s（含回放） | 帧率够，但数据质量不合格 |

CSI 是**接收端**测量：AP 要收到 STA 发来的帧才有 CSI。只发下行不够，必须让终端产生上行 QoS Data（ping 即可触发 ICMP 回包）。

### 5.2 重臂机制

实测固件 022 的 latch 是一次性的：

csi=1 → 锁存 2 个 PPDU（4 链共 8 帧）
→ csi_buffer_cnt 停在 used(8)，10 秒不增长
→ 必须 csi=0; csi=1 重新武装


重臂参数：每 100ms 一次，dwell 60–80ms 后轮询读取。已封装在 csilib.CSICapture(rearm_interval=0.1, rearm_dwell=0.08)。

### 5.3 读取方式

/proc/net/wlan/csi_data_* 的读行为在不同状态下会变：有时非阻塞立即返回 0，有时会阻塞。统一用：

os.open(path, O_RDONLY | O_NONBLOCK)
select.select([fd], [], [], 0.002)
os.read(fd, 65536)


cat 会立即 EOF 生成 0 字节文件，不能作为“没有 CSI”的依据。

### 5.4 走动协议

- 终端（手机/笔记本）放在桌面当固定锚点，**不要拿在手上**；
- 人空手，从 CPE 与终端连线侧面约 0.5m 处，**垂直穿过连线**来回走；
- 来回 15–20 趟，约 30 秒；
- 静止段 30–40 秒作对照；
- 用人工标记录制（用户起身回“走”、坐下回“坐”），按消息时间戳对齐，避免固定时间表导致“人还没走就结束”。

## 六、走动识别算法

### 6.1 特征

每帧 64/256 个子载波幅度 amp[k]
→ 按帧均值归一化：a[k] = amp[k] / mean(amp)   （消除 AGC/RSSI 整体缩放）
→ 4 秒滑窗内逐子载波计算标准差 std[k]
→ 取中位数作为运动分 score = median(std[k])


中位数的作用：抑制少数受窄带干扰/空子载波影响的子载波。

### 6.2 判决

阈值 threshold = 静默基线 p95 × 2.5
score > threshold        → 有人活动
score < threshold 持续 12s → 无人/静默


### 6.3 伪代码

calibrate(30s 静止):
    baseline = scores[]
    threshold = percentile(baseline, 95) * 2.5

loop:
    frame = read_csi()
    amp = |I + jQ|
    a = amp / mean(amp)
    push a into window(4s)
    score = median(std(window, axis=subcarrier))
    if score > threshold: state = ACTIVE; last_active = now
    elif now - last_active > 12s: state = IDLE


### 6.4 已知边界

- 人完全静止（屏息、坐着不动）时可能判静默；
- 邻居 AP、微波炉、蓝牙会造成误报；
- 多链/多速率/多 AGC 档位混采会让本底噪声升高一个数量级；
- 不能识别人数、身份、跌倒。

## 八、结果分析

### 8.1 数据质量指标

| 指标 | 实测 | 正常稳定信道预期 |
|---|---|---|
| 归一化幅度帧间 std（本底） | 0.32–0.48 | 0.01–0.05 |
| 相邻帧相关系数 | 0.2–0.4 | > 0.9 |
| 同帧相邻子载波相关 | 0.99 | 0.9+ |
| 走/坐运动分比值 | 0.97–1.06 | > 2 |

同帧相邻子载波相关 0.99，说明 CSI 本身是真实、平滑的信道频响；问题出在帧与帧之间不可比。

### 8.2 根因一：一次性快照，重臂回放

- csi=1 后只锁存 2 个 PPDU，csi_buffer_cnt 10 秒停在 used(8)；
- 重臂能继续出帧，但会重复回放旧帧：Beacon 相邻帧相关 1.000；90 秒 9218 帧中 pkt_sn 只有 255 个值；
- 10Hz 重臂标称 1080 帧/10s，真实新 PPDU 只有约 19 个/s。

### 8.3 根因二：单链锁定无效，四链混采

mwctl ra0 set csi=2-7-0-0 执行后，rx_path 仍均匀分布：

rx_path=0: 2440 帧   rx_path=1: 2370 帧
rx_path=2: 2262 帧   rx_path=3: 2146 帧


同一 pkt_sn 四链幅度均值：chain0=921、chain1=857、chain2=165、chain3=426（差 5 倍）。走动引起的变化只有 1–5%，被链间差异完全覆盖。

### 8.4 根因三：速率/AGC 跳变

不同帧的 MCS、发射功率、AGC 档位不同，整帧幅度会跳变（实测同链内存在约 920 与 760 两档）。按帧均值归一化能消掉整体缩放，但消不掉不同速率下的频响形状差异。

### 8.5 根因四：netlink 无连续流

csi_genl family 存在（id 28），但 ra0-auto-1000 只回 1 条、ra0-auto-100 10 秒 0 条。文档描述的 auto report 在本固件未生效。

### 8.6 工程副作用

约 2000 次 csi=0/csi=1 后，2.4G CSI 引擎彻底卡死（0 帧，Beacon 也不出），csi_debug_0 残留清不掉的空 STA 条目；只有 wifi restart 才恢复。重臂只能用于短时取证。

## 九、与业界方案对比

| 维度 | RSSI 感知 | 本方案 CSI（当前） | 华为 AI-FTTR（公开口径） |
|---|---|---|---|
| 数据 | 单个强度值 | 64/256 子载波 I/Q | 多天线 CSI + 场景模型 |
| 走动检测 | 粗粒度、易误判 | 理论可行，当前数据不支持 | 商用宣称支持 |
| 采样 | 每包一个值 | 依赖固件连续上报（当前不具备） | FTTR 终端内闭环 |
| 模型 | 规则/阈值 | 规则/阈值 | 10 万级场景训练 |
| 成本 | 零 | 零（固件受限） | 专用硬件 + 训练数据 |

结论：不能把“能采 CSI”等同于“能做感知”；华为的差距不只在 CSI，还有连续采集、标定、模型和闭环。

## 十一、结论与后续路线

### 11.1 结论

1. CSI 能采、能解析、能复现（2.4G 64 / 5G 256 子载波，真实 I/Q）；
2. 当前固件不能提供连续、单链、稳定速率的 CSI，走动识别不可行；
3. 五轮实测（2.4G×3、5G×2）检出率均为 0，走/坐运动分比值 0.97–1.06；
4. 卡点在固件，不在算法；换频段、换走位、换终端都解决不了。

### 11.2 后续路线

| 优先级 | 动作 | 说明 |
|---|---|---|
| P0 | 向 MTK 确认连续采集/单链锁定/netlink auto 用法 | 见 §十二 问题清单 |
| P1 | 若 MTK 提供连续固件，重跑同样五轮实验 | 现有脚本可直接复用 |
| P2 | 短期对外只讲干扰监测/自动选信道/RSSI 活动感知 | 不承诺走动感知 |
| P3 | 评估替代方案（毫米波、UWB、红外阵列） | 需另行评估成本与隐私 |

## 十二、需要 MTK 支持的事项（问题、日志、诉求）

### 12.1 问题 1：proc 模式只锁存 1–2 个 PPDU，没有连续采集

**现象**：csi=1 后硬件只锁存少量 PPDU，之后 10 秒缓冲区计数不再增长；不重臂时 8 秒 0 帧。

**日志（设备实测）**：

# mwctl ra0 set csi=0; mwctl ra0 set csi=2-3-0-34; mwctl ra0 set csi=1
# 连续 10 秒不读，每秒观察 /proc/net/wlan/csi_debug_0：

## 附录 D：常见疑问（FAQ）

**Q1：为什么在 CPE 侧测，不是在手机侧测？**

CSI 由接收机测量。CPE 作为 AP 接收手机的上行帧，所以 CPE 是接收端、手机是发射端。手机侧要测 CSI 需要驱动开放，实际不可行；AP 侧测量是业界标准做法（华为 FTTR 同理）。信道互易，人走过改变的是手机与 CPE 之间的多径，CPE 在上行帧上测到的幅度/相位同样会变。

**Q2：要不要拿着手机走动？**

不要。手机是固定锚点；拿着手机走测到的是“手机在动”，不是“人穿过房间”，基线也会被带偏。正确做法是手机放桌面，人空手垂直穿过手机与 CPE 的连线。

**Q3：为什么一定要让手机发上行帧？**

CSI 只对“收到的帧”测量。手机空闲时上行帧很少，CPE 侧 ping 它可逼出 ICMP 回包，这些回包就是 CSI 素材。

**Q4：2.4G 和 5G 哪个更适合？**

5G 80MHz 有 256 个子载波，频率分辨率更高；但实测两频段受同一个固件 latch 限制，结论一致。当前固件下换频段不改变结果。

**Q5：现在能不能对外说“能做走动感知”？**

不能。五轮实测检出率均为 0，走/坐运动分比值 0.97–1.06。可以讲“CSI 原始数据可采、干扰监测/自动选信道/RSSI 活动感知可做”，不能讲“无设备人体走动感知”。
