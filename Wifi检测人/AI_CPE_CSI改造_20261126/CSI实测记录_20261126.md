## 2. CSI 帧类型实测

### QoS Data（frame_type=34）

对灯泡持续 `ping -i 0.02 -s 1200`，CSI 配置成功：

```text
fix_chain(0) rc=0
frame_type(34) rc=0
start rc=0
```

但 6 秒内 **0 帧**。说明当前 Matter 灯泡的低速心跳/ICMP 流量没有命中 QoS Data 过滤，不能用来测走动。

### Beacon（frame_type=32）

同样 `ra0`，改抓 beacon：

```text
15.1 秒：746 帧
平均：49.5 帧/s
唯一 pkt_sn：190（约 25.5%）
RSSI 平均：-88.7 dBm
```

结论：CSI 采集链路本身正常；**QoS Data 路径需要真实数据终端**。

## 3. 静态误报测试

用 15 秒 beacon 静态录制回放 BK 状态机：

| 阈值 | 结果 |
|---|---|
| BK 默认 `thres1=5` | 190 个唯一帧中 **97 帧被判 motion**，明显误报 |
| 静默段 p95×1.5 = **109.17** | **0 帧 motion**，0 事件 |

说明：

- BK 的 5/3/8 阈值不能直接用于 MT7992；
- 必须先做静默段校准；
- 校准后静态场景可以做到 0 误报。

## 4. csi_daemon 在线集成

启动：

```bash
python3 csi_daemon.py --iface ra0 --port 18098 --frame-type 32 --algorithm bk
```

4 秒后 `/api/state`：

```json
{
  "algorithm": "bk",
  "state": "no_motion",
  "frames": 443,
  "fps": 37.6,
  "present": false,
  "move_rate": 0.0,
  "error": null
}
```

说明：新状态机已接入在线守护进程，能接收真实 CSI 帧，不是只跑离线脚本。

## 6. 结论与下一步

### 结论

- CSI 采集链路可用；
- BK 状态机已实装，静态场景校准后无误报；
- **真人走动检测尚未被证明**：现有走动样本没有形成运动/静默分离，且现场没有 QoS Data 客户端。

### 下一步

1. 让手机 HONOR-90 或笔记本连接 `ra0`，产生 QoS Data；
2. 用 `walk_test.py --target <手机IP>` 做 20 秒静止 / 30 秒走动 / 20 秒静止；
3. 用 `analyze_bk.py` 同时输出 move_rate 与 state，不以默认阈值 5 作结论；
4. 只有静默段 0 误报、运动段连续检出，才对外说“人体检测有效”。
