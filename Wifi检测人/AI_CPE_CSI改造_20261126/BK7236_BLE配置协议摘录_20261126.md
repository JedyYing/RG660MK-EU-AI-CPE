# BK7236 CSI BLE 配置协议摘录与映射

日期：2026-11-26
来源：`Wifi检测人/BK7236/bk_idk/projects/wifi/csi/main/`
（`bk_csi_ble_provision.c`、`bk_csi_ble_provision.h`、`armino_main.c`）

## 1. 广播与连接

| 项 | 值 |
|---|---|
| 广播名 | `bk_csi_demo_<MAC后3字节>` |
| 16-bit Service Data UUID | `0xFE01` |
| 厂商 ID | `0x05F0`（Beken） |
| 配置写入 opcode | `0xA5`（低字节） |
| 设备上报 opcode | `0x5A`（低字节，高字节为分段信息） |
| 单包通知上限 | 247 字节 payload（加 5 字节头） |

> 这是 Beken demo 的 `ble_boarding` 通用通道，不是标准 Matter/BLE GATT 服务。不要原样暴露到公网。

## 2. 配置下发帧

BLE 写入：

```text
opcode = 0xA5
data   = csi_code(2B LE) | json_len(2B LE) | JSON UTF-8
```

`csi_code = 17`（`CSI_BOARDING_OP_START_CSI_CONFIG`）。

大 JSON 会按 `0xA5` 分段：`opcode` 高字节编码 `seg_num/seg_count`；设备按 `cur_seg_count==0` 开始缓存，最后一段拼好后调用 `csi_data_rcv_data_handle()`。

## 3. 配置 JSON 字段

以下字段名直接来自 `armino_main.c` 的 `cJSON_GetObjectItem()`：

| 字段 | 类型/范围 | 含义 | 本机映射 |
|---|---|---|---|
| `code` | 1 | 1=启动配置 | `POST /api/config` |
| `ssid` | string | STA/AP SSID | 采集器 SSID |
| `password` | string | STA/AP 密码（不写日志） | 采集器密码 |
| `tx_type` | 0..2 | Beken 发送类型 | 不适用 MT7992 |
| `rx_mode` | 0..2 | Beken 接收模式 | 不适用 |
| `format` | 0..7 | CSI 输出格式 | TLV/IQ/amp |
| `is_resp_null` | 0/1 | 对应 `csi_work_type` | 事件模式 |
| `interval` | ms | 算法/上报间隔 | `--interval` |
| `interval2` | ms | 运动中重配置间隔 | 状态机参数 |
| `mode` | int | `csi_work_mode` | 采集模式 |
| `type` | 1/2 | 1=STA，2=AP | 拓扑 |
| `rate1/2/3` | 1..1023 | 算法速率参数 | 保留 |
| `thres1` | 1..99 | 动态变化阈值 | `BKConfig.thres1` |
| `thres2` | 1..99 | 状态变化阈值 | `BKConfig.thres2` |
| `thres3` | 1..99 | 静态变化阈值 | `BKConfig.thres3` |
| `thres4` | 1..99 | 运动中重配置阈值 | `BKConfig.thres4` |
| `static_update` | <3600000 | 静默基线更新周期（×interval） | `static_update` |
| `hold_time` | <3600000000 | 运动保持/无人确认 | `hold_time` |
| `calibration_cnt` | <3600000 | 校准帧数/计数 | `calibration_cnt` |
| `cali_mode` | 0..3 | 校准模式；1=清变化标志 | `calibration_cnt` 辅助 |

默认值（BK demo）：

```json
{
  "code": 1,
  "ssid": "<ssid>",
  "password": "<password>",
  "tx_type": 0,
  "rx_mode": 0,
  "format": 0,
  "is_resp_null": 0,
  "interval": 100,
  "interval2": 100,
  "mode": 0,
  "type": 1,
  "rate1": 8,
  "rate2": 16,
  "rate3": 8,
  "thres1": 5,
  "thres2": 3,
  "thres3": 8,
  "thres4": 8,
  "static_update": 15000,
  "hold_time": 0,
  "calibration_cnt": 200,
  "cali_mode": 0
}
```

注意：

- `thres1..4` 是 Beken 算法的特征量纲，**不能直接套到 MT7992 的 `move_rate`**；本机必须用静默段校准。
- `password` 不应进入普通日志、URL 或 Git；在设备上使用 0600 文件或内存注入。

## 4. 设备上报帧

设备通知：

```text
opcode = 0x5A | (segment << 8)
header = opcode(2B LE) | status(1B) | payload_len(2B LE)
payload = JSON UTF-8
```

`csi_ind_send_to_app()` 产生的 JSON：

```json
{"csi_ind": 0, "csi_result": 0}
```

`csi_result` 语义：

| 值 | 含义 |
|---|---|
| 0 | empty / 无人 |
| 1 | motion / 有人活动 |
| 2 | static change / 静态环境变化 |

Beken demo 还在本地用 RGB 灯显示：

- 绿色 = empty；
- 粉色 = motion；
- 蓝色 = static change。

## 5. 与本机看板/API 的映射建议

当前 `csi_sensing` 已有：

```text
GET  /api/state       # 实时特征
GET  /api/events      # motion_start/motion_end
POST /api/calibrate   # 20s 静默校准
```

若要对齐 BK 的 BLE 语义，建议增加：

```text
POST /api/config
  body: 上述 JSON 字段
  response: {"ok": true, "algorithm": "bk", "thresholds": {...}}

GET /api/state
  state: "no_motion" | "motion"
  state_static: "empty" | "change"
  move_rate / state_rate
```

注意：我们的 `state_rate` 是“相对静默基线”的代理量，不宣称等于 Beken 的 `state_change_rate`。

## 6. 安全边界

- Beken demo 的 BLE boarding 没有应用层认证/加密；不要把该通道直接用于量产。
- 如果后续在本机实现配置接口，应加：
  - 仅本机/局域网绑定；
  - 一次性 token 或已配对 BLE 绑定；
  - SSID/密码不写入日志、不进入 Git；
  - 配置变更审计（来源、时间、字段差异）。
