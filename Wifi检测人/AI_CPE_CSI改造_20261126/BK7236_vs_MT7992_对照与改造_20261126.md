# BK7236 Wi‑Fi CSI 检测方案 vs RG660MK / MT7992 现状

日期：2026-11-26
参考代码：`/home/jedyying/RG660MK-EU-AI-CPE/Wifi检测人/BK7236/bk_idk/projects/wifi/csi/`
本机实现：`/data/ai_cpe/csi_sensing/`

## 1. 结论摘要

BK7236 这套代码是一个**完整的 Wi‑Fi CSI 人体活动参考方案**：

```text
CSI 原始数据 → 固件算法事件（move_change_rate / state_change_rate）
→ 应用层状态机（无人 / 有人 / 静态变化）
→ 板载 RGB 灯 / BLE 结果回传
```

它可以复用 **状态机、阈值语义、BLE 配置协议**；但 **不能直接移植检测算法**：Beken 的 DSP 在 `libwifi_csi.a` 中闭源，项目源码只是应用层。

RG660MK 使用 MT7992，当前能通过 `mwctl set csi=` 采原始 CSI，但：

- 固件 022 的 CSI latch 只锁存少量 PPDU，需要 100ms 重臂；
- 重臂导致同一 `pkt_sn` 重复回放，帧间相关约 0.5；
- 现有 4 秒方差检测在两次真机录制中检出率均为 **0%**；
- 本次新增 BK 风格状态机后，按静默基线校准阈值，仍未检出，说明瓶颈在 CSI 数据质量，不是状态机。

## 2. BK7236 代码结构

| 文件 | 内容 |
|---|---|
| `projects/wifi/csi/main/armino_main.c` | CSI 初始化、`EVENT_WIFI_CSI_ALG_IND`、状态机、参数解析 |
| `projects/wifi/csi/main/bk_csi_common.h` | `csi_wifi_alg_t`、`csi_wifi_config_t`、状态和阈值 |
| `projects/wifi/csi/main/bk_csi_ble_provision.c` | BLE 广播/分段/JSON 配置/结果回传 |
| `projects/wifi/csi/main/bk_csi_demo.c` | 用 6 个 GPIO 的 RGB 灯显示结果 |
| `components/bk_libs/bk7236/libs/libwifi_csi.a` | CSI 算法库（闭源） |
| `include/modules/wifi_types.h:789` | `move_change_rate` / `state_change_rate` 事件结构 |

关键代码路径：

```c
// armino_main.c
bk_wifi_csi_info_cb_register(wifi_csi_rx_cb_demo);
...
case EVENT_WIFI_CSI_ALG_IND:
    csi_wifi_alg_result_handle(
        csi_data_info->move_change_rate,
        csi_data_info->state_change_rate);
```

`csi_wifi_alg_result_handle()` 是**状态机**，不是 DSP：

```text
NO_MOTION:
  move_change_rate > thres1 连续 4 次 → MOTION
  （可选）static_update / calibration_cnt 自动校准
MOTION:
  move_change_rate <= thres1 连续 4 次 → NO_MOTION
  state_change_rate > thres3 且持续 → STATIC_CHANGE
```

默认参数：

```text
thres1=5, thres2=3, thres3=8, thres4=8
rate1=8, rate2=16, rate3=8
static_update=15000
calibration_cnt=200
hold_time=0
motion_consecutive=4
```

## 3. 本机 MT7992 现状

### 3.1 已有能力

- `csilib.CSICapture`：`mwctl` 配置 + 非阻塞 `proc` 读取 + 100ms 重臂；
- TLV 解析：RSSI/SNR/BW/PCI/ARFCN/`pkt_sn`/I/Q/amp；
- `MotionDetector`：4 秒滑窗逐子载波 std + 帧间差；
- `csi_daemon`：`:8098` 看板、`/api/state`、`/api/events`、`/api/calibrate`；
- 录制/离线评估：`csi_record.py`、`walk_test.py`、`analyze_motion.py`。

### 3.2 已存在的问题

- CSI latch 一次性，不重臂只有 0.1–0.8 帧/s；
- 10Hz 重臂后约 90–110 帧/s，但同一 `pkt_sn` 重复；
- 2.4G 录制 750 帧只有 93 个唯一 `pkt_sn`（约 12%）；
- 帧间相关约 0.5，不能当稳定信道；
- 两次走动录制 legacy 检出率 **0%**，分离度 1.03 / 0.98。

## 4. 可复用 / 必须重写

| 模块 | BK7236 | 本机处理 | 结论 |
|---|---|---|---|
| CSI 采集 | 固件回调 | `mwctl` + proc + 重臂 | **重写** |
| 变化率算法 | 固件 `libwifi_csi.a` | `bk_state.py` 的幅值差分代理 | **重写/近似** |
| 状态机 | `csi_wifi_alg_result_handle` | `BKStateMachine` | **复用逻辑** |
| 阈值 | 5/3/8/8 | 必须按静默段重新校准 | **不可照搬** |
| BLE 配置 | BLE boarding JSON | 尚未实现 | **可复用协议** |
| 结果输出 | RGB 灯 + BLE | HTTP `/api/state` | **映射复用** |

新增/修改：

```text
csi_sensing/bk_state.py       # BK 风格 move_rate/state_rate + 状态机
csi_sensing/analyze_bk.py     # 离线评估 + 阈值校准

csi_sensing/test_bk_state.py  # 合成帧回归
```

`bk_state.py` 的特征定义：

```text
move_rate  = 相邻唯一帧归一化幅度的平均绝对差 × 100
state_rate = 当前帧相对静默基线的归一化幅度平均绝对差 × 100
```

这不是 Beken 的原始 DSP，只是可解释的代理特征；阈值必须由静默段校准。

## 6. 实测对比

样本：`data/samples/sample_2g_walk_152405.jsonl.gz`
750 帧，93 个唯一 `pkt_sn`，pre/motion/post 各 250 帧。

### legacy（4 秒方差）

```text
fps = 84.66
pre score p50/p95 = 0.355 / 0.379
motion score p50/p95 = 0.367 / 0.390
threshold = 0.9487
detect_ratio = 0.0
separation = 1.03
```

### BK 风格状态机

```text
唯一帧使用率 = 108/750 = 14.4%
静默段 move_rate p50/p95 = 24.59 / 64.59
运动段 move_rate p50/p95 = 14.48 / 52.50
按静默 p95×1.5 校准阈值 = 96.88
detect_ratio = 0.0
pre 误报率 = 0.0
```

> 如果直接使用 BK 默认阈值 `thres1=5`，预录段会被判为运动（误报很高）。这说明 **阈值不能跨芯片照搬**。

### 结论

- 状态机逻辑可以复用；
- 但这批 MT7992 录制没有形成“运动段高于静默段”的变化率分离；
- 不能对外宣称“已实现 Wi‑Fi 人体检测”；
- 需要先解决 CSI 数据质量（netlink/连续流/固件），再评估状态机。

## 7. 建议

1. **短期**：保留 `--algorithm bk` 作为实验模式，默认仍以状态机记录特征和事件，不把“motion”当产品结论。
2. **中期**：拿 MTK 的连续 CSI 模式或修复 latch/重臂重复问题；用同一套 `bk_state.py` 重测。
3. **长期**：若需 Beken 级检测，优先获取 MTK 官方 sensing SDK/算法库；不要尝试从 `libwifi_csi.a` 反编译搬运。
4. **数据纪律**：所有报告必须标注唯一帧比例、fps、频段、终端型号和录制时长；不能把 90 帧/s 当成 90 个独立 PPDU/s。
