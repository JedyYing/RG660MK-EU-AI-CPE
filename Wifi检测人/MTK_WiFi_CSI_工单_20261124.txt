主题：RG660MK（MT7992，CSI fw 022）CSI 连续采集与单链锁定问题咨询

MTK FAE / 产品经理：

我们在 RG660MK（MediaTek T930 + MT7992，OpenWrt 23.05）上按《Connac3 CSI Spec Requirement v1.2》实现了 CSI 采集，原始 I/Q 可以正常读出（2.4G 64 子载波、5G 80MHz 256 子载波，单帧 351B，TLV 格式与文档一致）。但在做人体走动感知时发现三个固件层面的问题，导致数据无法用于感知，请协助确认。

一、实测问题（均有原始数据与复现脚本）

1. proc 模式只支持一次性快照
   - mwctl ra0 set csi=2-3-0-34 后 set csi=1，只锁存 2 个 PPDU（4 链共 8 帧）；
   - 之后 10 秒 csi_debug_0 的 csi_buffer_cnt 恒为 used(8)，不再增加；
   - 必须 csi=0/csi=1 重臂才会继续出帧，但重臂会重复回放旧帧（Beacon 相邻帧相关系数 1.000，90 秒 9218 帧中 pkt_sn 仅 255 个值）；
   - 高频重臂约 2000 次后，2.4G CSI 引擎完全停摆（0 帧），只有 wifi restart 才恢复。

2. 单链锁定命令无效
   - 执行 mwctl ra0 set csi=2-7-0-0 后，帧内 rx_path 仍为 0/1/2/3 均匀分布（2440/2370/2262/2146 帧）；
   - 同一 pkt_sn 四条链的幅度均值相差 5 倍（921/857/165/426），无法做单链 CSI 分析。

3. netlink 模式无连续上报
   - csi_genl family 存在（id 28）；
   - ra0-auto-1000 只回 1 条消息，ra0-auto-100 在 10 秒内 0 条；
   - 未找到可用的连续上报方式。

二、希望确认的问题

1. proc 模式是否支持连续采集？是否有“连续/循环”参数或推荐固件版本？csi=1 后只锁存 1–2 个 PPDU 是否为已知问题？
2. 锁定单条 RX 链的正确命令/参数是什么？csi=2-7-0-0 是否只对 TX 天线生效？
3. csi_genl 的 auto report（ra0-auto-xxx）正确用法是什么？需要哪个固件版本才能稳定连续上报？

三、附件与证据

- 《RG660MK Wi-Fi CSI 感知评估报告 V3》（6 页，含 5 轮实测数据与根因）
- 2.4G / 5G 走动样本（各 750 帧，JSONL）
- csi_debug_0/1 输出与首帧 hex（可随时提供）
- 复现脚本：csilib.py / rec_marker.py / csi_netlink.py

如果这些功能需要特定 SDK 或 NDA，也请告知申请流程。盼复，谢谢。
